# My-Vault – Production-Ready Full-Stack Documentation

**Stack:** React 19 + Tailwind CSS v4 + Vite (frontend) · Node.js 24 + Express 5 + TypeScript (backend) · PostgreSQL + Prisma · Docker (backend only) · Postman

> **Core principle:** The master key never leaves the browser. The server stores only a salted Argon2id hash of the derived auth verifier, the wrapped DEK, and encrypted credential records. There is no email, no application login password, and no admin approval — the master key is the only credential.

## 4. Master-key access flow (the only authentication)

### 4.1 Vault setup (first run)

1. `GET /api/v1/vault/metadata` → `404` if no vault exists.
2. Browser generates a random 16-byte salt.
3. Browser runs Argon2id with the user's master key, producing **64 bytes**:
   - `bytes[0..31]` → **KEK** (wraps the DEK)
   - `bytes[32..63]` → **auth verifier** (sent to server)
4. Browser generates a random 256-bit DEK and wraps it with the KEK using AES-256-GCM.
5. Browser calls `POST /vault/setup` with `salt`, `kdfParameters`, `wrappedVaultKey`, `keyNonce`, and `authVerifier`.
6. Server hashes `authVerifier` with Argon2id, stores the vault row, and creates a session cookie.
7. Dashboard opens. The DEK stays in browser memory only.

### 4.2 Unlock (subsequent visits)

1. `GET /vault/metadata` → `200` with salt, KDF params, wrapped DEK.
2. User enters the master key.
3. Browser re-derives KEK + auth verifier.
4. Browser attempts to unwrap the DEK. Failure → **wrong master key** (no request sent).
5. Success → browser sends `POST /vault/unlock` with the auth verifier.
6. Server verifies against the stored Argon2id hash, creates a session, sets cookie.
7. Browser fetches encrypted credentials, decrypts locally, renders dashboard.

**Recovery:** if the master key is lost, the DEK cannot be recovered. State this on the setup screen.

## 5. API endpoints

Base path: `/api/v1`

All responses use `{ success: boolean, message?: string, data?: any }`.

### 5.1 Vault APIs

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/vault/metadata` | Public | Return salt, KDF params, wrapped DEK, nonce. `404` if no vault. |
| `POST` | `/vault/setup` | Public (only if no vault) | Create vault + open session. `409` if vault exists. |
| `POST` | `/vault/unlock` | Public | Verify auth verifier + open session. `401` on failure. |
| `POST` | `/vault/lock` | Session | End server session. |
| `PUT` | `/vault/key-envelope` | Session | Update envelope after master-key change. |

**`GET /vault/metadata` — 200**

```json
{
  "success": true,
  "data": {
    "kdfAlgorithm": "ARGON2ID",
    "kdfParameters": { "memoryKiB": 65536, "iterations": 3, "parallelism": 4, "outputLength": 64 },
    "salt": "BASE64_SALT",
    "keyEncryptionAlgo": "AES-256-GCM",
    "wrappedVaultKey": "BASE64_WRAPPED_DEK",
    "keyNonce": "BASE64_NONCE",
    "encryptionVersion": 1
  }
}
```

**`POST /vault/setup` — request**

```json
{
  "kdfAlgorithm": "ARGON2ID",
  "kdfParameters": { "memoryKiB": 65536, "iterations": 3, "parallelism": 4, "outputLength": 64 },
  "salt": "BASE64_SALT",
  "keyEncryptionAlgo": "AES-256-GCM",
  "wrappedVaultKey": "BASE64_WRAPPED_DEK",
  "keyNonce": "BASE64_NONCE",
  "authVerifier": "BASE64_AUTH_VERIFIER",
  "encryptionVersion": 1
}
```

**`POST /vault/unlock` — request**

```json
{ "authVerifier": "BASE64_AUTH_VERIFIER" }
```

### 5.2 Credential APIs (session required)

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `POST` | `/credentials` | Create encrypted credential |
| `GET` | `/credentials` | List encrypted credentials |
| `GET` | `/credentials/:id` | Get one encrypted credential |
| `PUT` | `/credentials/:id` | Update with optimistic concurrency |
| `DELETE` | `/credentials/:id` | Delete |

**Create — request**

```json
{
  "ciphertext": "BASE64_ENCRYPTED_CREDENTIAL",
  "nonce": "BASE64_NONCE",
  "encryptionVersion": 1
}
```

**Update — request** (includes `expectedRecordVersion`)

```json
{
  "ciphertext": "BASE64_NEW_CIPHERTEXT",
  "nonce": "BASE64_NEW_NONCE",
  "encryptionVersion": 1,
  "expectedRecordVersion": 1
}
```

Return `409` when `expectedRecordVersion` does not match.

### 5.3 CSRF + test endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/csrf` | Return CSRF token for session-authenticated state-changing requests |
| `GET` | `/health` | Health check (`{ success: true }`) — used by Docker health check |

## 6. API key types (for Postman testing)

You asked for **different types of API keys** for testing. There are exactly **two** in this application:

| Key type | Where it lives | What it does |
| --- | --- | --- |
| **Master key** | User's head / browser memory | Derives the KEK and auth verifier. Never sent to the server. |
| **Test API key** (`TEST_API_KEY`) | Backend `.env` + Postman environment | Sent as `X-Test-API-Key` header. **Only active when `TEST_MODE=true`.** Bypasses CSRF and relaxes rate limits so Postman/Newman can run tests quickly. |

**Test API key middleware (`src/common/middleware/testApiKey.ts`):**

```ts
import { Request, Response, NextFunction } from "express";
import { env } from "../../config/env";

export function testApiKey(req: Request, res: Response, next: NextFunction) {
  if (env.TEST_MODE !== "true") return next();

  const key = req.header("X-Test-API-Key");
  if (key && key === env.TEST_API_KEY) {
    (req as any).isTestRequest = true;
  }
  next();
}
```

Apply it globally in `app.ts`:

```ts
app.use(testApiKey);
```

Then in `csrfProtection`, skip CSRF when `req.isTestRequest` is true:

```ts
export function csrfProtection(req: Request, res: Response, next: NextFunction) {
  if ((req as any).isTestRequest) return next(); // test API key bypass
  // normal CSRF validation...
}
```

> **Never** set `TEST_MODE=true` in production. The `.env.example` defaults to `true` for local development only.

## 7. CORS configuration

The frontend and backend run on different ports in development, so CORS must allow the frontend origin and credentials (cookies).

`src/app.ts`:

```ts
import cors from "cors";
import { env } from "./config/env";

const allowedOrigins = [env.CLIENT_ORIGIN];

app.use(
  cors({
    origin(origin, callback) {
      if (!origin || allowedOrigins.includes(origin)) {
        return callback(null, true);
      }
      callback(new Error("Not allowed by CORS"));
    },
    credentials: true,
    methods: ["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"],
    allowedHeaders: ["Content-Type", "Authorization", "X-CSRF-Token", "X-Test-API-Key"],
  })
);
```

Key rules:

- **Never** use `origin: "*"` with `credentials: true` — browsers reject it, and it is a security risk.
- Use an explicit allowlist checked on every request.
- In production, set `CLIENT_ORIGIN` to your exact deployed frontend URL (e.g. `https://vault.example.com`).
- `app.options("*", cors())` is not needed when the middleware is applied globally before routes.

## 8. Backend Dockerfile (backend only)

`backend/Dockerfile` — multi-stage build with a non-root user, `tini` for signal handling, and a health check:

```dockerfile
# syntax=docker/dockerfile:1

# ── Stage 1: production dependencies ─────────────────────
FROM node:24-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN --mount=type=cache,target=/root/.npm \
    npm ci --omit=dev --no-audit --no-fund

# ── Stage 2: build TypeScript ────────────────────────────
FROM node:24-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN --mount=type=cache,target=/root/.npm \
    npm ci --no-audit --no-fund
COPY tsconfig.json ./
COPY prisma ./prisma
RUN npx prisma generate
COPY src ./src
RUN npm run build

# ── Stage 3: runtime ─────────────────────────────────────
FROM node:24-alpine AS runner
WORKDIR /app
RUN apk add --no-cache tini
ENV NODE_ENV=production

RUN addgroup --system --gid 1001 appgroup \
 && adduser  --system --uid 1001 --ingroup appgroup appuser

COPY --from=deps    --chown=appuser:appgroup /app/node_modules ./node_modules
COPY --from=builder --chown=appuser:appgroup /app/dist        ./dist
COPY --from=builder --chown=appuser:appgroup /app/prisma      ./prisma
COPY --chown=appuser:appgroup package.json ./

USER appuser
EXPOSE 5000

HEALTHCHECK --interval=30s --timeout=10s --retries=3 --start-period=30s \
  CMD ["node", "-e", "fetch('http://localhost:5000/api/v1/health').then(r=>{if(!r.ok)process.exit(1)}).catch(()=>process.exit(1))"]

ENTRYPOINT ["/sbin/tini", "--"]
CMD ["node", "dist/server.js"]
```

`.dockerignore` (backend):

```
node_modules
dist
.env
*.log
```

Build and run:

```bash
cd backend
docker build -t my-vault-backend .
docker run --env-file .env -p 5000:5000 my-vault-backend
```

For local development with a database, use Docker Compose with `postgres` and the backend service; the frontend runs separately with `npm run dev`.

## 13. Security checklist (V1)

- [ ] Master key never reaches the backend.
- [ ] KEK and unwrapped DEK never leave the browser.
- [ ] Server stores only an Argon2id hash of the auth verifier.
- [ ] `POST /vault/setup` returns `409` if a vault already exists.
- [ ] AES-256-GCM with a fresh 12-byte nonce per encryption.
- [ ] AAD binds ciphertext to credential ID + vault ID + encryption version.
- [ ] Session cookies: `HttpOnly`, `Secure` (production), `SameSite=Strict`.
- [ ] CSRF protection on all state-changing session requests (bypassed only by `X-Test-API-Key` when `TEST_MODE=true`).
- [ ] Rate limiting on `/vault/unlock` and `/vault/setup`.
- [ ] CORS allowlist — never `origin: "*"` with credentials.
- [ ] `TEST_MODE=false` in production.
- [ ] Auto-lock after 3 minutes inactivity; max unlock 5 minutes.
- [ ] Refresh requires re-entering the master key.
- [ ] No decrypted data in `localStorage`, `sessionStorage`, IndexedDB, or cookies.
- [ ] No secrets in logs or error responses.
- [ ] Database backups tested.
